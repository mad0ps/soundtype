# Сборка терминала с починенным выделением

Что чиним:

1. **Выделение не работает поверх TUI-приложений** (`vim`, `htop`, `tmux`,
   Claude Code). Пока программа просит передавать ей события мыши, терминал
   не делает собственного выделения — протяжка уходит программе. Пункт
   `Copy` из-за этого всегда неактивен.
2. **Падение при выходе из режима выделения.** Обработчик нажатия на нижнюю
   плашку уничтожает объект, внутри которого сам выполняется, и продолжает
   работать в освобождённой памяти.

Первое требует правки нативной библиотеки, поэтому нужен компьютер: на
телефоне нет компилятора и поставить его некуда — корень только для чтения.

## Что нужно на ноутбуке

* Docker (`clickable` собирает внутри контейнера, ничего в систему не ставит)
* Python 3
* Телефон, подключённый по USB, с включённым режимом разработчика

```sh
pipx install clickable-ut     # или: pip install --user clickable-ut
clickable --version
```

## Сборка

```sh
git clone --recurse-submodules \
  https://gitlab.com/ubports/development/apps/lomiri-terminal-app.git
cd lomiri-terminal-app

# правки лежат в этом каталоге проекта soundtype/patches/
git apply --directory=libs/qmltermwidget \
  /путь/к/0001-qmltermwidget-writable-terminalUsesMouse.patch
git apply /путь/к/0002-terminal-app-selection-and-crash.patch

clickable build --arch arm64
```

Собранный `.click` появится в `build/arm64-linux-gnu/app/`.

## Установка на телефон

Через USB, если телефон подключён:

```sh
clickable install --arch arm64
```

Либо скопировать `.click` на телефон и поставить там **без root** —
`pkcon` для click-пакетов не годится (бэкенд PackageKit здесь `aptcc`, он
только про `.deb`), нужен привилегированный сервис:

```sh
gdbus call --system --dest com.lomiri.click \
  --object-path /com/lomiri/click \
  --method com.lomiri.click.Install ~/имя-пакета.click
```

## Что проверить после установки

| Сценарий | Ожидание |
|---|---|
| Выделение + нижняя плашка в чистой вкладке, 5 раз подряд | не падает, копируется |
| То же под `htop` | **теперь копируется** — это и есть суть правки |
| То же под Claude Code | копируется |
| Попап через кнопку в шапке | открывается, пункты активны |
| Попап долгим тапом | открывается, пункты активны |
| Закрыть и открыть приложение | без неожиданностей |
| `journalctl -f` во время всего этого | ни одного `TypeError` |

Отдельно: `SIGABRT` при закрытии приложения к этим правкам отношения не
имеет, это давний отдельный дефект. Не спутать.

## Чего эти правки НЕ чинят

`QMLTermWidget` не поддерживает **OSC 52** — управляющую последовательность,
которой консольные программы кладут текст в системный буфер. Поэтому
автокопирование при выделении внутри самих программ (Claude Code и подобных)
по-прежнему уходит в никуда: программа считает, что скопировала, буфер
остаётся пустым. Это отдельная задача в той же библиотеке.
