# Задание для сборки на ноутбуке

Этот файл — постановка задачи. Всё исследование уже сделано на телефоне,
здесь только сборка и проверка. Не нужно заново диагностировать: причины
установлены и подтверждены опытами, они описаны ниже.

## Что собираем

Терминал Ubuntu Touch `lomiri-terminal-app` с двумя правками. Патчи лежат
рядом с этим файлом, инструкция по сборке — в `BUILD.md`.

## Установленные факты, которые не надо перепроверять

**Дефект 1 — выделение не работает поверх TUI-приложений.**
Когда запущенная программа включает передачу событий мыши (`vim` с
`set mouse=a`, `htop`, `tmux`, Claude Code), `QMLTermWidget` отдаёт указатель
программе и собственного выделения не строит. Режим выделения при этом
выглядит рабочим, но `terminal.isSelectionEmpty()` остаётся истинным, и
пункт `Copy` в меню приходит неактивным.

Проверено опытом: в чистой вкладке без TUI выделение и копирование
работают; в той же вкладке под Claude Code — нет.

Отпустить мышь из QML нельзя: свойство объявлено только на чтение.
`Q_PROPERTY(bool terminalUsesMouse READ getUsesMouse NOTIFY usesMouseChanged)`
в `libs/qmltermwidget/lib/TerminalDisplay.h`. Сеттер `setUsesMouse(bool)` в
том же заголовке уже существует, он просто не подключён к свойству. Отсюда
патч `0001` — одна строка.

Важно: свойство называется `terminalUsesMouse`, а НЕ `usesMouse`. Попытка
писать в `usesMouse` даёт `TypeError: Cannot assign to read-only property`.

**Дефект 2 — падение при выходе из режима выделения.**
Обработчик `onClicked` нижней плашки первым делом переводит
`terminalPage.state` в `"DEFAULT"`. Состояние `SELECTION` держит
`bottomMessage.active = true`, поэтому смена состояния заставляет `Loader`
синхронно уничтожить плашку вместе с этим самым `MouseArea`. Следующая
строка вызывает `PopupUtils.open` уже в освобождённой памяти — процесс
падает с `munmap_chunk(): invalid pointer`, сигнал `SIGABRT`.

Патч `0002` откладывает всё содержимое обработчика через `Qt.callLater`,
сохраняя исходный порядок действий.

## Чего эти правки НЕ чинят

`QMLTermWidget` не реализует **OSC 52**. Консольные программы, которые
копируют этой последовательностью (в том числе Claude Code при выделении
мышью), получают молчаливый отказ: программа считает, что скопировала, а
буфер пуст. Это отдельная задача в той же библиотеке, в текущие патчи не
входит. Не пытаться чинить заодно — сначала нужно проверить то, что есть.

## Ловушка, на которой мы уже спотыкались

`SIGABRT` возникает **и при обычном закрытии** приложения — это давний
отдельный дефект (у них issue #117). Дважды принимали его за наше падение и
делали неверные выводы. При проверке смотреть не на сам факт `SIGABRT`, а на
то, что ему предшествует в журнале: наше падение шло следом за четырьмя
строками `UCLabel was created without a valid QML Engine`.
