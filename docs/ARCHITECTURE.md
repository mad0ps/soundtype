# Как устроено

Приложение состоит из двух половин: интерфейс на QML и вся работа со звуком
на Python. Между ними — [pyotherside](https://github.com/thp/pyotherside),
QML-плагин, который умеет звать python-функции и принимать события обратно.

```
                    ┌─ downloader.py ──▶ докачка модели и библиотек
                    │
  Main.qml ──вызовы─┼─ backend.py ──ctypes──▶ libpulse-simple   (микрофон)
     ▲              │      │
     │              │      ├──────────────▶ silero VAD          (нарезка)
     └───события────┘      └──────────────▶ Parakeet            (распознавание)
                    │                        через sherpa-onnx
                    └─ streaming.py ──▶ Segmenter + DecodeWorker
```

Ни `torch`, ни компилятора: `sherpa-onnx` ставится готовым колесом под
`cp38/aarch64`, модель уже в формате ONNX с квантованием int8.

**Модули:**

| Файл | Ответственность |
|---|---|
| `py/backend.py` | Запись, расшифровка, история, связь с QML |
| `py/streaming.py` | Нарезка потока на фразы и фоновое распознавание. Про pyotherside не знает — только колбэки, поэтому тестируется на любой машине |
| `py/downloader.py` | Докачка модели и колёс. Тот же код зовут и кнопка в приложении, и `scripts/fetch-deps.py` |

## Обмен между QML и Python

**QML зовёт Python** (`py.call("backend.<имя>", [аргументы], обработчик)`):

| Функция | Что делает |
|---|---|
| `init()` | Проверяет наличие модели, грузит её в фоновом потоке |
| `start()` | Начинает запись |
| `stop()` | Останавливает запись |
| `retry(ts)` | Переспрашивает модель по сохранённому звуку записи `ts` |
| `fetch_deps()` | Качает модель и библиотеки |
| `history_list()` | Возвращает историю, новые записи первыми |
| `history_clear()` | Стирает историю вместе со звуком |

**Python шлёт события** (`pyotherside.send(...)`), QML ловит через
`setHandler`. Всего шестнадцать:

| Событие | Аргументы | Когда |
|---|---|---|
| `deps-missing` | чего нет | Модель не найдена, нужен экран загрузки |
| `download-progress` | этап, % | Ход докачки (`-1` — этап без прогресса) |
| `download-done` | — | Всё скачано |
| `download-error` | сообщение | Обрыв или отказ |
| `status` | — | Началась загрузка модели |
| `ready` | имя модели | Модель загружена, кнопка ожила |
| `recording` | `bool` | Запись началась / закончилась |
| `elapsed` | секунды | Тик таймера во время записи |
| `level` | 0…1 | Громкость, для кольца вокруг кнопки |
| `partial` | номер, текст | Фраза распозналась **по ходу записи** |
| `transcribing` | `bool` | Идёт добор оставшихся фраз |
| `progress` | номер, всего | Разбор очередной фразы |
| `final` | текст, `ts` | Готовая расшифровка целиком |
| `done` | текст | Всё завершено — QML кладёт текст в буфер |
| `retried` | `ts`, текст | Результат повторного распознавания |
| `error` | сообщение | Любая ошибка |

Каждое событие должно иметь пару в `Main.qml`. Если добавляешь новое — не
забудь `setHandler`, иначе оно потеряется без предупреждения. Проверить
соответствие можно так:

```sh
grep -oE "emit\('[a-z_-]+'" py/backend.py | sort -u
grep -oE 'setHandler\("[a-z_-]+"' qml/Main.qml | sort -u
```

## Запись и распознавание

Цикл чтения микрофона не делает ничего тяжёлого — только читает и отдаёт
куски дальше. Это принципиально: любая заметная работа в этом цикле приводит
к переполнению буфера PulseAudio и **потере живой речи**. На этом уже
обжигались, см. `DECISIONS.md`.

```
libpulse-simple (ctypes)
    формат    s16le, 16 кГц, моно
    чтение    по 8192 байта = 4096 отсчётов = 0.256 с за раз
    предел    MAX_RECORD_SECONDS = 600 (около 38 МБ в памяти)
        │
        ├──▶ копится в память целиком (для истории и повтора)
        │
        └──▶ Segmenter.feed()   окна по 512 отсчётов
                  │              порог 0.5, тишина 0.35 с, речь от 0.20 с
                  │              максимум фразы MAX_SPEECH = 30 с
                  ▼
             DecodeWorker (отдельный поток)
                  │  Parakeet TDT 0.6B v3 int8, 4 потока
                  ▼
             событие partial ──▶ текст появляется на экране живьём
```

После остановки добираются оставшиеся в очереди фразы, тексты склеиваются
пробелом и уходят как `final`, затем `done`.

**Ловушка sherpa-onnx #2918:** декодировать нужно **только сегмент**, никогда
весь накопленный буфер. Иначе результат портится. Это учтено в `DecodeWorker`.

Если детектор не нашёл ни одной границы, вся запись уходит в модель целиком —
лучше так, чем молча вернуть пустоту.

Скорость: около 0.27 секунды счёта на секунду аудио. Загрузка модели при
старте — примерно 5 секунд.

## Что где лежит

```
~/.local/share/soundtype.n0madd3v0ps/
├── models/
│   ├── parakeet/
│   │   ├── encoder.int8.onnx     652 МБ
│   │   ├── decoder.int8.onnx      12 МБ
│   │   ├── joiner.int8.onnx        6 МБ
│   │   └── tokens.txt             словарь
│   └── silero_vad.onnx           644 КБ
├── runtime/pylibs/               numpy + sherpa_onnx, распакованные колёса
├── history.jsonl                 по строке JSON на расшифровку: ts, text
└── audio/<ts>.wav                звук последних AUDIO_KEEP = 20 записей
```

`history.jsonl` дописывается построчно, а перезаписывается целиком только
при повторном распознавании — когда надо заменить текст одной записи.
Ограничение `HISTORY_LIMIT = 500` применяется при чтении, файл не обрезается.

Каталог `runtime/pylibs` добавляется в `sys.path` первой строкой
`backend.py` — до импорта `numpy` и `sherpa_onnx`.

## Докачка зависимостей

При старте `init()` проверяет `downloader.missing()`. Если чего-то нет —
шлёт `deps-missing`, и QML показывает экран с кнопкой «Скачать» вместо
неработающей кнопки записи.

Колёса распаковываются через `zipfile`: `pip` на устройстве отсутствует, а
колесо — обычный zip. Модель Parakeet приходит архивом `tar.bz2`, из него
берутся четыре нужных файла.

Загрузка идёт во временные пути и переносится на место только целиком —
обрыв связи не оставит битую модель. Повторный вызов во время уже идущей
загрузки просто выходит, не начиная вторую.

## Буфер обмена

Отдельного API для буфера у конфайнированного приложения нет. Используется
обходной приём: скрытый `TextEdit`, в него кладётся текст, дальше
`selectAll()` и `copy()`.

Выглядит как костыль, но это рабочий путь. Попытка вызвать `CreatePaste`
службы `com.lomiri.content.dbus.Service` напрямую по D-Bus из консоли не
проходит — буфер привязан к графической поверхности, а у консольной
программы её нет.

## Права

`soundtype.apparmor`:

```json
["microphone", "audio", "keep-display-on", "networking"]
```

`networking` нужен только для докачки модели. `content_exchange` не нужен —
копирование через `TextEdit` работает и без него.

В журнале при запуске всегда будут отказы AppArmor на
`/sys/devices/system/cpu/*` — это `onnxruntime` пытается определить процессор.
Не ошибка, но из-за них он не видит возможностей ядра и считает медленнее.

## Сборка

`click build` требует, чтобы рядом с `manifest.json` лежали только файлы
приложения. Поэтому `scripts/build.sh` собирает содержимое в `build/soundtype/`
и пакует уже оттуда, а не из корня репозитория.

Модель и библиотеки в пакет **не входят** — они живут в каталоге данных и
переустановку приложения переживают.
