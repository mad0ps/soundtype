# SoundType

Офлайн-диктовка для Ubuntu Touch. Говоришь — получаешь текст в буфере обмена.

Распознавание целиком на телефоне: ни одного байта наружу, ни облаков, ни
ключей. Работает в самолётном режиме.

Сеть нужна ровно один раз — скачать модель при первом запуске. Дальше
интернет не требуется вообще.

**Статус:** рабочая версия 0.6.0, ежедневно используется. Не в OpenStore —
ставится из исходников, см. [Установку](#установка).

---

## Как этим пользуешься

1. Жмёшь зелёную кнопку — идёт запись, в шапке тикает таймер.
2. Говоришь. Сколько угодно, с паузами, мешая русский с английским.
   **Текст появляется по ходу речи**, а не только в конце.
3. Жмёшь красную — добираются оставшиеся фразы.
4. Готовый текст сохраняется в историю и **сразу ложится в буфер обмена**.
5. Переходишь в любое приложение и вставляешь.

Расшифровка занимает примерно четверть длительности записи: минута речи
считается секунд пятнадцать (Snapdragon 690, четыре потока).

### Почему распознавание рядом с записью, а не внутри неё

Это главное архитектурное решение, и оно не косметическое. Цикл чтения
микрофона **только читает** и отдаёт куски дальше. Нарезка на фразы и
распознавание живут в отдельном потоке.

В ранней версии распознавание вызывалось прямо из цикла чтения. На каждой
паузе цикл замирал на секунду с лишним, буфер PulseAudio переполнялся, и
живая речь **терялась** — длинные сообщения приходили обрезанными.

Если будешь трогать этот код, держи правило: в цикле чтения ничего тяжёлого.
Подробности и история разворотов — в [`docs/DECISIONS.md`](docs/DECISIONS.md).

### История

Каждая расшифровка сохраняется в `history.jsonl` с отметкой времени. Тап по
записи копирует её заново.

Для последних 20 записей сохраняется и сам звук — у них появляется кнопка
повторного распознавания. Полезно, когда первый заход сорвался: не хватило
памяти, приложение свернули, распознавание оборвалось. Модель
детерминированная, поэтому на исправном звуке повтор даст тот же результат —
это не «попробовать ещё раз, вдруг лучше».

Минута речи занимает около 2 МБ, старые записи удаляются автоматически.

## Требования

| | |
|---|---|
| Система | Ubuntu Touch 20.04 (Focal), arm64 |
| Место | ~1.5 ГБ: модель 660 МБ, библиотеки 130 МБ |
| Память | ~1.1 ГБ на время работы приложения |
| Компилятор | **не нужен** — и модель, и библиотеки ставятся готовыми сборками |

## Установка

```sh
git clone https://github.com/mad0ps/soundtype.git
cd soundtype

./scripts/build.sh     # собирает click-пакет
./scripts/install.sh   # ставит в систему
```

Модель качать заранее не нужно: при первом запуске приложение само предложит
кнопку «Скачать» и покажет прогресс. Около 500 МБ, делается один раз — при
пересборке приложения модель не трогается.

Если удобнее из командной строки, есть тот же путь:

```sh
python3 scripts/fetch-deps.py
```

> `pkcon install-local` здесь не работает в принципе — бэкенд PackageKit на
> Ubuntu Touch это `aptcc`, он понимает только `.deb`. Установкой click-пакетов
> занимается служба `com.lomiri.click`, её и вызывает `install.sh`.

## Разработка

Правишь `qml/Main.qml` или `py/backend.py`, потом:

```sh
./scripts/build.sh && ./scripts/install.sh
```

Приложение перед установкой лучше закрыть, иначе останется работать старая
версия. Посмотреть, что оно пишет в журнал:

```sh
journalctl -f | grep -i soundtype
```

### С ноутбука, с доставкой на телефон

Собирать можно и не на устройстве. Телефон подключается по USB, `adb` из
Android SDK:

```sh
# собрать пакет локально (click нужен только для сборки)
./scripts/build.sh

# доставить и поставить
adb push build/*.click /home/phablet/
adb shell "gdbus call --system --dest com.lomiri.click \
    --object-path /com/lomiri/click --method com.lomiri.click.Install \
    /home/phablet/$(basename build/*.click)"
```

Модель и библиотеки живут на **телефоне**, в каталоге данных приложения.
Скачиваются там один раз — кнопкой при первом запуске или `fetch-deps.py`.
Пересборка и переустановка их не трогают.

Стандартный инструмент разработки под Ubuntu Touch — `clickable`: собирает в
докере и заливает по USB. Наши скрипты ему не мешают, они просто про сборку
на самом устройстве.

## Что не доделано

* **Модель висит в памяти постоянно** (~1 ГБ), даже когда приложение простаивает.
  Выгрузки по бездействию нет.
* **AppArmor не пускает `onnxruntime`** к `/sys/devices/system/cpu/*`, поэтому он
  не определяет возможности процессора и считает медленнее, чем мог бы. В
  журнале это `Unknown CPU vendor`.
* **Нет автоповтора при сбое** распознавания одной фразы — она просто теряется,
  в лог пишется ошибка.
* **Не в OpenStore.** Главное препятствие снято — докачка модели теперь внутри
  приложения. Осталась сама публикация: оформление, снимки экрана, проверка на
  чистом устройстве.
