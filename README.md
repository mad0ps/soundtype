# SoundType

Офлайн-диктовка для Ubuntu Touch. Говоришь — получаешь текст в буфере обмена.
Никаких облаков и ключей: распознавание целиком на телефоне.

Движок — [Parakeet TDT 0.6B v3](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3)
от NVIDIA через [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx). Одна модель
на 25 языков, русский и английский можно мешать в одной фразе.

## Как это работает

1. Жмёшь зелёную кнопку — идёт запись, в шапке таймер. Распознавание в это
   время не работает вообще, поэтому терять на паузах нечего.
2. Жмёшь красную — вся запись режется детектором тишины на фразы и уходит
   в модель. Видно прогресс: «Расшифровываю… 3 из 7».
3. Готовый текст попадает в поле, в историю и **сразу в буфер обмена**.
   Переходишь в любое приложение и вставляешь.

Расшифровка занимает примерно четверть от длительности записи: минута
речи считается секунд пятнадцать (Snapdragon 690, 4 потока).

История хранится в `~/.local/share/soundtype.n0madd3v0ps/history.jsonl`,
тап по записи копирует её заново.

## Требования

* Ubuntu Touch 20.04 (Focal), arm64
* Около 1.5 ГБ свободного места: модель занимает ~660 МБ, библиотеки ~130 МБ
* Около 1.1 ГБ оперативной памяти на время работы приложения

Компилятор не нужен: и модель, и python-библиотеки ставятся готовыми
сборками под `cp38/aarch64`.

## Установка

```sh
git clone https://github.com/<пользователь>/soundtype.git
cd soundtype

# Качает модель и библиотеки (~500 МБ) в каталог данных приложения
python3 scripts/fetch-deps.py

# Собирает click-пакет
./scripts/build.sh

# Ставит его в систему
./scripts/install.sh
```

Первый шаг долгий — качается почти полгигабайта. Его достаточно сделать
один раз: при пересборке приложения модель не трогается.

## Разработка

Правишь `qml/Main.qml` или `py/backend.py`, потом:

```sh
./scripts/build.sh && ./scripts/install.sh
```

Приложение перед установкой лучше закрыть, иначе останется работать старая
версия. Посмотреть, что оно пишет в журнал:

```sh
journalctl -f | grep -i soundtype
```

### Как устроено

```
qml/Main.qml     интерфейс: кнопка, поле текста, экран истории
py/backend.py    запись звука, нарезка на фразы, распознавание, история
manifest.json    описание click-пакета
soundtype.apparmor  права: микрофон, звук
```

Обмен между QML и Python идёт через
[pyotherside](https://github.com/thp/pyotherside): QML зовёт
`backend.start()` / `backend.stop()`, Python шлёт события обратно
(`recording`, `elapsed`, `transcribing`, `progress`, `final`, `done`).

Звук берётся напрямую из `libpulse-simple` через `ctypes` — так надёжнее,
чем поднимать GStreamer внутри конфайнмента.

## Известные шероховатости

* Модель держится в памяти всё время работы приложения (~1 ГБ). Выгрузка
  по бездействию пока не сделана.
* AppArmor не пускает `onnxruntime` к `/sys/devices/system/cpu/*`, из-за
  чего он не определяет возможности процессора и считает чуть медленнее,
  чем мог бы. В журнале это видно как `Unknown CPU vendor`.
* Кнопки «повторить распознавание» в истории пока нет.

## extras/

Не относится к самому приложению, но пригодилось по дороге:

* `fix-terminal-crash.py` — чинит падение `terminal.ubports` (SIGABRT,
  повреждение кучи) при выходе из режима выделения текста. Обработчик
  уничтожал объект, внутри которого сам выполнялся. Запускать от root.
* `terminal-app-patch/` — тот же фикс в виде патча против апстрима
  `lomiri-terminal-app` вместе с текстом issue и merge request.
